## 2026 1분기 회고

26년이 시작한지 얼마 지나지 않은 것 같은데 1분기가 끝나갑니다. 시간이 빠르게 지나간다는 말을 매 회고때마다 하는 것 같습니다.

### 새로운 조직 구성 그리고 새로운 목표

파트가 ~~폭파~~ 새로 되었습니다. 기존에 하던 BDA 서비스를 보다 주도적으로 책임지게 되었고 기능적으로도 일부를 담당하는 것이 아닌 전체 커버리지를 담당하도록 되었습니다.

이전 조직 구성에서는 영역을 나뉘어 가진 상태로 출발했기 때문에 R&R 에 있어서도 약간의 모호한 점 이 있고 어느 누구도 주인이라고 여기기 어려웠습니다.

어떻게든 책임을 나눠가며 하긴 했지만 이도 저도 아닌 구석이 있긴 했습니다.

그렇게 정리가 되었고 그 과정에서 이전 파트에서 하던 일은 전략적으로 축소하는 방향이 되었습니다.

새로운 사람들과 일하는 것은 어려움도 있고 즐거움도 있습니다. 조직 관점에서 고인물이 되지 않으려면 일부의 순환은 필요하다고 합니다. 

오히려 저는 외부에서 온 사람이고 구성원들은 기존 사람들에 가까운 형태로서 적당히 섞여 있습니다.

특히나 이 파트는 작년에 많은 어려움을 겪었습니다. 잦은 PM 의 교체와 프로젝트 방향성의 큰 수정으로 인해 트라우마가 남아 있는 듯 했습니다.

예전 파트장은 그 정신적 피로감으로 직을 내려 놓을 정도였으니까요.

혼란한 상황에서 파트를 맡게 되었고 이전 PM 은 한분은 장기 교육에 들어가셨고 한분은 개발팀으로 오시게 되었습니다. 실질적인 PM 은 한 분인 셈 이었습니다.

상황이 이렇다 보니 저도 어쩔 수 없이 연초에 계획을 세우고 방향성을 만들어 감에 있어 어려움이 다가왔습니다. 

남겨지신 PM 도 상당히 당혹스러움과 동시에 험난한 길을 헤쳐 나가야 한다는 부담감이 큰 상황이었습니다.

저는 개인적으로 상황을 탓하지 않습니다. 언제나 어려움과 곤란함과 모호함은 존재합니다. 인생이 그렇다고 생각하는 편 입니다.

문득 어렸을 적에 읽었었던 '누가 내 치즈를 옮겼을까?' 내용이 떠올랐습니다. 중요한 문제 는 치즈가 아닙니다. 

누가 옮겼을 지를 고민하고 생각하기 보다는 그래서 내가 어떻게 행동하고 나아가야 할 것인가를 고민합니다.

연초에는 계획을 많이 세웁니다. 계획대로 된 적은 없더라도 파트 그리고 서비스에 대해서도 계획을 같이 세웁니다.

제가 작년에 지켜 보면서 느꼈던 부분, 그리고 PM 측에서 제안하는 아이디어와 내부 의견들, 전체를 모아서 로드맵 장표를 일단 만들어 봅니다.

혹여 누군가는 왜 개발 파트장이 이런것까지 하느냐고 묻기도 합니다. 뭐 안될 이유가 있을까요?

물론 제가 잘 한다고 할 수는 없습니다. 저도 자신 없습니다. 전략을 잘 세우는 것도 어렵구요.

그래도 누군가는 해야하고 필요하다면 한다는 생각으로 합니다. 없는 것 보다는 낫겠지요.

한편으로는 제가 계획을 세우면 그 주도권은 제가 가지고 있다고 생각합니다. 

회사생활 하다보니 결국 두가지 입니다. 이끌거나, 이끌리거나.

기왕이면 이끄는 사람이 되는 것이 더 좋지 않을까요? 회사생활 하면서 스트레스도 받고 힘들기도 하지만 성취감과 효용감을 느끼는 것에 있어, 전자의 경우가 크더군요.

물론 시간이 부족하고 파트원 분들과 대화를 많이 나눌 시간은 부족 했습니다. 어찌보면 독단적인 판단으로 성급한 결정을 했을지도 모르겠습니다. 

그래도 갈피를 못잡고 흔들리는 리더십 보다는 독단적인 계획을 세우는 편이 나을수 있다고 생각합니다. 

### 사람이 미래다

국내 모 대기업의 카피 문구였었던 내용이지만 AI Agent 시대에서의 사람의 역할은 여전히 유효합니다.

물론 AX 의 결론이 인건비 절감일 수 있겠으나 AI 가 완전한 대체가 되기는 어려워 보이기 때문입니다. 

우스갯소리로 사무실에 사람 대신 GPU 하나씩 올려두면 되는 것이 아니냐 라고 하는데 어느정도 맞는 말이기도 한데 아니기도 합니다. (뭔소리?)

올해 초부터 OpenClaw 의 열풍이 불었습니다. Agent 에게 제한적인 Tool 을 주는것에서 넘어 이제 전권을 맡겨 버리는 구조입니다.

예전에는 기껏 줘봤자 스크립트 몇개 실행시켜주는 것, 브라우저 조금 주는 것, 검색 엔진 결과 좀 주는 것에서 넘어

시스템 전체를 맡겨 버립니다. 

이제 OpenClaw 를 잘 쓰면 비행기 예약시키면서 카드 결제까지도 맡겨버리고 주식 투자도 스스로 사고팔게 할 수 있습니다.

물론 이전에도 불가능 했던 것은 아니었습니다. 어떤 클라우드 내의 sandbox 조금이 아닌 이제 내 컴퓨터 전체를 제공 하니까요.

sudo 권한도 주고 systemd 도 줘버립니다. 어떠한 소프트웨어도 설치 할 수 있고 특별히 물어보지도 않습니다.

자칫하면 악성코드를 설치할 수도 있고 내 중요한 개인정보나 암호를 해커에게 보낼 수도 있습니다.

그런데 그런건 극단적인 상황이겠죠. 통상적으로 좋은점도 많습니다.

내 개인 비서처럼 시키는 명령을 잘 따릅니다. 노가다 작업도 잘 하고, 주기적으로 체크하는 것도 잘 합니다.

문제는 비용입니다. LLM API 비용이 생각보다 많이 발생합니다. 내가 이미 비서를 고용하고 있다면 대체가 될 수 있겠으나

원래 비용은 없던건데 뭔가 추가 고용을 해야만 하는 것 같아서 아깝기도 합니다. (없어도 그만...)

하지만 기업에서 라면 얘기가 달라집니다. 단순한 정리 작업을 주로 하거나 매뉴얼식의 작업을 하는 일이라면 대체하기 쉽겠죠

회사 내부 데이터와 정보에 접근할 수 있는 범위가 넓은 사람일 수록 할 수있는 일들이 많아 질 것 같습니다.

예를들면 임원들... 임원들... 임원들 이겠네요.

관료제 구조속에서 최상단으로 올라갈 수록 추상화의 레벨이 높아집니다. 말단 실무에서는 구체적인 작업을 수행하는 것이고, 최상단에서는 추상화된 질문이나 명령을 던지게 됩니다.

그것이 아래 단계로 전달이 되면서 더 구체화되고 명확해 집니다.

예를들면 CEO 가 우리회사의 AX 는 왜 잘안될까? 라고 질문을 하게되면

그 아래 전략조직에서는 각 기능별로 AX 프로젝트 현황을 점검하고 재무조직에서는 과제들의 AI 비용을 검토할 것이고, 

보안 부서에서는 프로세스의 허들이나 리스크 요소를 확인하고, IT 나 개발조직에서는 AI 모델과 툴의 성능을 비교하며 분석할 것입니다.

더 아래 조직에서는 현장의 목소리를 취합 할 것이고 과제별로 각각 상황에 맞게 대책을 수립해서 보고하겠죠.

이러한 상황에서 Context 의 양을 생각한다면 상단에 있는 CEO 가 각 과제의 문제점을 다 파악할 필요는 없습니다. 알기도 어렵고 이해하는데도 쉽지 않습니다.

중간 레벨에서 누군가가 취합을 하고 공동점을 파악하고 통계화를 하여 정량화 할 것입니다. 기준을 설정할 것이고 그 에 맞게 자료들이 정리 되겠죠.

그렇게 최종 보고서는 몇 장안되는 페이지에 전체 커버리지의 내용들이 정리되어 보고될 것입니다.

이러한 workflow 를 AI Agent 를 통해 만들게 하려면 어떻게 해야할까요?

대상이 수백, 수천명이라면 그 모든 사람의 memory 와 context 를 모델링 해야 할 것입니다. 수 년간 쌓아온 경험과 지식의 노하우를 모델링 한다.....

결코 쉽지는 않습니다. LLM 이 가장 표준화 되어 인류의 지식을 담고는 있지만 모든 지식을 다 알고 있는 것은 아니거든요.

이렇게 보면 사람이 미래다 라기 보다는 **사람의 데이터가 미래다** 라고 보는 것이 맞겠습니다.

### 데이터는 안녕 하신가요?

제 소속은 빅데이터 센터입니다. 데이터 양적으로는 몇백PB 수준의 큰 데이터를 가지고 있습니다. 비용도 많습니다.

그런데 데이터 사용자들로 부터 불만이 많습니다. 데이터를 어떻게 써야할지 모르겠다. 어떻게 찾아야 할 지 모르겠다.

사람마다 데이터 분석 역량의 편차가 있고, 다루는 데이터가 다르기도 한데, 대체적으로 불만이 많습니다.

빅데이터 센터의 역사 동안 데이터의 커버리지, 품질, 메타 관리에 큰 노력을 기하지 못했다고 봅니다.

보여주기식 성과에 매몰되어 근본적인 문제를 해결하지 못하고 기초 체력을 키우지 못했습니다.

저도 모르는 부분이 많았습니다. 

데이터 관리의 트렌드가 어떻게 변화하고 있는지, 데이터 또한 하나의 Product 로 만들어 관리해야 하는 사실들,

제품의 공급망 처럼 데이터 또한 공급 체인이 있어야 한다는 사실들, 품질 관리에 큰 노력을 기해야 한다는 사실들 ...

그리고 타 기업들의 전략과 운영 방법들에 대해서  따라가지 못하고 AI 신기술만 따라갔던 현실이 문제인 것 같습니다.

비정형 데이터는 AI Agent 에 있어서 필요한 데이터를 공급하여 RAG 만 잘 해도 어느정도 유욯한 정보를 제공 할 수 있습니다.

LLM 이 비정형 데이터를 이해를 잘 하기 때문입니다.

그런데 정형 데이터는 결이 조금 다릅니다. 

데이터의 정리와 분류 체계와 품질이 갖춰져있는 상태에서 데이터의 위치와 의미와 연결 정보들이 명확하게 정의 되어있을 때,

비로소 분석가가 분석하는 것 처럼 따라할 수 있습니다.

아마 이 부분에 대한 해결은 2분기 부터 시작하지 않을까 싶습니다. 

원래 계획에 있었던 것은 아니지만 급박한 사정으로 인해서 촉발된 이슈가 전사적으로 대두되고 있고 어쨋든 해결 할 수 있도록 노력 해봐야겠습니다.

결국 AX (AI Transformation) 가 잘되려면 Data 가 잘 있어야 하고 Data 가 잘 있다는 뜻은 DX (Data Transformation) 가 이뤄져야 합니다. 

너무나도 당연한 이야기이며 지난 2년동안 겪은 시행착오의 결론이지만 왜 해결이 어려울까요.

누군가도 나서지 않았기 때문인 것 같아요.
